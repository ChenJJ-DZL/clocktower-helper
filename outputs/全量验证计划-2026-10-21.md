## 0. 先把话说死：什么算「全部验证过」

「全部验证过」= 下面 5 条**同时**成立，且每一条都有**一条命令能跑、能报红**的判据：

| # | 判据 | 完成线 |
|---|---|---|
| C1 | **角色覆盖**：9 剧本 × 各自全部角色 = **191 个 (剧本,角色) 二元组**，每个都在该剧本的 E2E 里**实跑过至少 1 局** | 191 / 191 |
| C2 | **技能生效**：每个角色在实跑局里**真的被唤醒过**（主动）或**被动规则被判据覆盖过**（被动），且**每个分支至少 1 条判据** | 角色 100% × 分支表 100% |
| C3 | **弹窗内容**：每个可达弹窗都被 E2E 打开过，且文案与**已批准基线**逐字一致；不可达弹窗**零 ENTRY_LOST** | 43 可达 / 0 ENTRY_LOST |
| C4 | **环节顺序**：每局的实际唤醒顺序 **= 官方 JSON rank 过滤后的顺序**（不只看「弹窗序 = 队列」） | 每局 0 偏差 |
| C5 | **整局合规**：每个剧本每局都跑到终局，终局四条判据通过，不变量 **违例 0** | 9/9 剧本 × N 局 × 0 违例 |

**明确不说（避免过度承诺）**：

- 说「全部验证过」指的是**按模型验证**：状态空间按「角色 × 分支」划分并 100% 覆盖，
  **不是**穷举对局树（那是无穷的）。
- 说书人**自由裁量**（如「另一名玩家可能代替你死亡」的选人）只按**分支枚举**覆盖到每种裁定的后果，
  不保证每个具体表述与某个真人说书人一致。
- 未包含：发版上线后的线上真机验证（属于发版流程，不在本计划）。

## 2. 必须先补的「测量基础设施」（没有它，后面的覆盖都是空话）

### W1 强制阵容注入（enabler，优先级最高）

**问题**：现在发牌是随机（`quickStartGenerator::shuffle` + `dealRng`），
要靠随机撞出「某个角色 × 某个剧本」得跑几十局，且不可控。
**做法**：给发牌器加一个**仅测试可用**的注入口（生产行为不变）：

```ts
// src/utils/quickStartGenerator.ts
// window.__CT_FORCE_LINEUP__ = { script: "暗流涌动", roles: ["imp","poisoner","chef",...] }
//   · 只在存在该全局对象时生效；
//   · 长度必须等于人数，阵营配额必须合法，否则**抛错拒绝发牌**（不静默回退随机）。
```

**验收**：
- 单测：注入合法阵容 ⇒ 发牌结果逐位相等；注入非法阵容 ⇒ 抛错（不静默）。
- E2E：同一个 `(剧本, 阵容)` 跑两次，`lineup` 完全一致。
- 生产路径：不注入时与今天完全一致（有回归用例）。

### W2 覆盖率台账 + 棘轮（已有雏形，需扩成双台账）

**做法**：
1. `outputs/coverage_ledger.json`（已实现）：`(剧本,角色) → seen/evidence`。
2. 扩字段：`e2e: { seen, games, woke, effectAsserted }`、`unit: { branchCases }`。
3. 新增棘轮测试 `src/utils/__tests__/coverage_ratchet.test.ts`：
   - 读台账 JSON；
   - **任何一格 `seen/woke/effectAsserted/branchCases` 比基线少 ⇒ 报红**；
   - 台账里的角色 id 必须属于该剧本 `roleIds`（防写错剧本）。

**验收**：把台账里任意一格改成 0 ⇒ 测试红；恢复 ⇒ 绿。

## 3. 五个维度怎么做（方法 + 判据 + 反例验证）

### C1 角色覆盖（W3）

| 项 | 内容 |
|---|---|
| 做法 | 按「每剧本每角色至少 1 局」生成阵容：5 人局（3 镇民 + 1 爪牙 + 1 恶魔）优先，外来者/爪牙/恶魔各按配额补；一个 11 人局可一次覆盖 11 个二元组 |
| 局数估算 | 191 个二元组 ÷ 每局平均 9 个新角色 ≈ **24~40 局**（含沉重复），按 40 局预算 |
| 判据 | 台账 `seen ≥ 1` 且 `evidence` 里的局**真的跑到终局**（不是失败的残留报告） |
| 反例验证 | 故意从某局报告里删掉一个角色名 ⇒ 台账该格归零 ⇒ 棘轮红 |

### C2 技能生效（W4 主动唤醒 + W5 分支矩阵）

**W4「真的醒了」判据**（E2E 侧）：
- 从夜序 journal 里读「本节唤醒的角色」，与该局阵容比对；
- 判据：`该角色在队列中` 且 `步骤被执行（弹窗/确认出现）` 且 `该步骤不是被跳过分支`；
- 夜间死亡或醉毒导致**允许**不唤醒的，必须由**判据自己**给出豁免理由（角色 + 原因），
  禁止按角色名白名单整体豁免（会把真 bug 一起放过）。

**W5 分支矩阵**（单测侧，最关键的一步）：
按**角色类别**建模板，逐角色枚举分支，每分支一条判据：

| 类别 | 必须覆盖的分支 |
|---|---|
| 击杀类 | 正常击杀 / 目标被保护 / 目标免死（士兵·弄臣·茶女…）/ 施法者醉毒 / 目标已死 / 转火（镇长）/ 连锁（月之子） |
| 信息类 | 正常真值 / 涡流必假 / 醉毒（可说书人给假）/ 特殊真值（修行者=最近邪恶方向；骑士=两人都非恶魔）/ 无信息（智者 found:false） |
| 保护类 | 生效 / 施法者醉毒 / 目标不在场 / 连续两夜不得同目标 |
| 干扰类 | 中毒/醉酒落地（座位状态必须真的变）/ 清除时机（黄昏/次日）/ 与毒免角色交互 |
| 转化类 | 善良→邪恶（写 `isEvilConverted`）/ 邪恶无效 / 全局一次 / 已死无效 / 酒鬼按伪装身份算 |
| 被动类 | 触发条件成立 / 不成立 / 与醉毒叠加 / 与胜负判定的先后 |
| 胜负类 | 通用四条 + **专属胜因**（圣徒/涡流/利维坦/剧本自动获胜）+ 同时成立时的善良优先 |

**判据独立性铁律**：判据**不得调用被测算角色的辅助函数**去算真值（自洽 ≠ 正确），
必须由测试自己按官方文本独立推。**每条判据都要有「能红」的反例单测**。

### C3 弹窗内容（W6）

1. **可达性收口**：22 条登记逐条**做决定**——
   - 有替代机制 ⇒ 写 `SUPERSEDED` + 替代物证据（保留登记）；
   - 纯残留 ⇒ **删除代码与类型**（台账同步删）；
   - 该有入口但丢了（`ROLE_INFO` / `ROLE_CODEX`）⇒ **今天就要选**：补入口，或删弹窗。
   **完成线：ENTRY_LOST = 0**（不许长期挂账）。
2. **文案基线**：每个可达弹窗做一次「人工批准 → goldens」：把首帧文本快照存进
   `src/utils/__tests__/fixtures/modal_goldens/<ModalType>.txt`，E2E 打开时比对。
   - 允许动态部分用占位符（`{{N}}号`、`{{role}}`）先归一化再比。
   - 关键句必须与 `officialRoleDocs.json` 一致（逐字），非关键句（UI 提示语）允许自由。
3. **判据**：43 个可达弹窗全部有 golden + E2E 至少打开 1 次。

### C4 环节顺序（W7）

补上 MEMORY 里点名的缺口：**「面板队列 = 执行队列」不等于「队列 = 官方夜序」**。

- 数据源：`src/data/officialRoleDocs.json` 之外的官方夜序 JSON（项目内已有 rank 解析器
  `nightOrderParser`），用**同一份官方数据**独立算出「今天这局应唤醒的顺序」；
- 判据：`实际唤醒序列 == 官方顺序 filtered by (在场 ∧ 存活 ∧ 有行动)`，逐位比对；
- 允许的例外必须**显式声明**（如洗脑告知的插入点、守鸦人二次唤醒），且例外本身要有判据。
- **反例验证**：把生成器里两个相邻角色的顺序对调 ⇒ 该判据必须红（I10 此时仍然全绿，
  这正是要补它的理由）。

### C5 整局合规（W8）

1. 每剧本 **≥ 5 局**（不同种子/阵容），全部 `requireGameOver` + `verifyTerminalOutcome`；
2. 不变量 I1~I14 每局全跑，**违例 0**；
3. 白天规则矩阵扩展为「按角色分支」：提名/投票取消/处决结算/免死/特殊胜因/镇长三存活/
   主谋额外一日/旅行者流放… 每条 1 个 E2E 或单测判据；
4. 每局报告必须落盘（`temp/<script>_<seed>.json`），台账从报告读，**不手填**。

## 7. 风险与反模式（都是本项目踩过的）

| 风险 | 具体形态 | 对策 |
|---|---|---|
| **判据空跑** | 判据依赖一个恒为 null 的输入（如 `duskExecs` 没落盘）⇒ 永远跳过却显示全绿 | 每条判据必须在报告里落「判到几条」，0 条即红 |
| **量错对象** | 用 `body` 里第一个「第 N 夜」判断状态（那是日志），误判 nightCount 冻结 | 只认 `[data-testid]` 或 state 真值 |
| **自洽当正确** | I10 只证「弹窗序 = 队列」，队列本身错了也绿 | C4 另起判据直接对官方 rank |
| **白名单豁免过宽** | 按角色名整体跳过（如「死亡触发类一律豁免」） | 只按**行为判据**豁免，且要求反证 |
| **skip / test.fail 掩盖** | 卡死改成 skip 就再也看不见 | 只允许 `test.fail()` + 明确原因，修好会变红逼着回收 |
| **随机不可复现** | 同 seed 两次不同阵容 | 只用 `dealRng` 种子 + W1 强制阵容 |
| **并行破坏闸门** | build 与 dev 抢 `.next`；E2E 与单测抢 CPU 导致 5s 超时 | 三闸门串行；E2E 与 vitest 不同时跑 |
